== Foreword

This is the compatibility language: the dialect every existing asciimath document is written in, specified so that its behavior is fixed — including its prohibition on growth. Features do not land here; they land in pma. The extension mechanism that does exist (the quoted channel) is Part 2.

== Scope

This document specifies the language surface, the compatibility contract, the closed deviation ledger, and the materialization of parsed trees into the math model.

== Normative references

* Plurimath 1 (the math model, the registry); asciimath 2 (extension channels)
* The asciimath.org dialect (compatibility baseline)

== The compatibility contract

. Every asciimath.org construct parses and renders with unchanged meaning.
. The ONLY permitted extensions ride the quoted channel of Part 2.
. Every behavioral deviation from asciimath.org is enumerated in the ledger (Clause "The deviation ledger"); additions require a part edition.

== Language surface

Numbers (decimals); unary and binary + −, multiplication, division, fractions, superscript/subscript, `sqrt(...)`; grouping parentheses; juxtaposition; the symbol vocabulary — `legacy`-tagged registry entries (Greek, arrows, relations, named operators). `±` and `+-` parse to the plain `Pm` symbol with no uncertainty semantics. The artifact generated from the registry edition is the normative grammar; this clause orients.

== The deviation ledger (closed)

|===
|Deviation |Kind |Rationale

|Quoted-string extensions (`"unitsml(...)"`, the uncertainty channel)
|additive
|Part 2; rides asciimath's own string literal

|Lenient fallback symbols (unrecognized tokens → letters)
|lenient
|never breaks an asciimath.org document

|Locale decimal rejection in ambiguity-prone contexts (`AmbiguousDecimalError`)
|strict
|prevents silent misreads; valid inputs unaffected

|Bareword uncertainty call forms (`ustd`/`uexp`/`ucov`)
|removed
|never released; re-homed as pma constructors (pma 1); standard asciimath has no uncertainty, so no corpus depends on them
|===

== Materialization into the math model

Parse trees map through the registry's primitive bindings into the Plurimath math model: one binding table, no per-language mapping code. A parser conforming to this part produces trees that the render corpus replays byte-identically across every format column.

== Absences (normative)

No uncertainty syntax, no `unit(...)` constructor, no measured literals, no `::` assertions, no conversion syntax. This list is exhaustive by construction: this dialect never grows.

== Conformance

The asciimath.org specimen corpus renders byte-identically; the ledger-audit test proves no unledgered divergence; the render corpus (UnitsML 8) replays the asciimath columns.
