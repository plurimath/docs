== Conformance

=== The conformance classes

An implementation conforms to this document at the class its corpus generation pins:

* the *arithmetic class* — PM 1004's corpus, unchanged;
* the *quantity class* — the construction, coherence and algebra vectors of PM 1009 plus the quantity evaluations of this document's clause 5;
* the *propagation class* — the GUM worked examples (H.1–H.6) reproduced to the documented precision, the correlation vectors, the coverage and dof vectors;
* the *second-order class* — the GUF₂ vectors, the normality-gate refusals, the LPU-adequacy verdicts;
* the *series class* — the aggregations and the type-A loop vectors;
* the *serialized class* — the JSON request/response parity vectors across the runtimes.

=== The acceptance

A conformance claim names the classes and the corpus generations. The classes are independent: arithmetic-only conformance is PM 1004's, unchanged; each new class stands on PM 1009 and this document's clauses for that class.

=== The corpus

A claim names the repository, the commit and the generations below, per class. The evaluator-reference generation sends each request verbatim and compares the expected wire byte for byte as canonical JSON; a stochastic row replays only with the identical method, generator and seeds, and `precision=approximate` marks a declared approximation, not a looser comparison.

=== Known gaps at the pinned commit

* *H.2.* The independent exact-input arithmetic is checked, but agreement with the last digit the GUM publishes is not established; it needs the original unrounded inputs or the source's rounding convention (`acceptance.json`, `unresolved`).
* *H.1.* The `h1-lpu-analytic` row carries the second-order terms: its standard uncertainty is 33.78 nm, against 32 nm at the first order. The row reproduces the second-order figure; a first-order H.1 row is not yet pinned.
* *H.5* is pinned only by the host-evaluator producer rows; the evaluator-reference generation has no H.5 row.
* The `numeric-annex-h` rows do not record which worked example each reproduces.
* *The serialized class.* The evaluator-reference wires are produced by the Rust evaluator and re-run byte-equal by the Ruby reference for the arithmetic families; cross-runtime parity for TypeScript is not yet pinned.
* The MCM rows were not re-run in the generation; they carry the generator, the seeds and the final state of their source run, per clause 7's boundary.
