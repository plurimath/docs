=== Reading

`Plurimath::Math.parse(text, :latex)` creates a `Plurimath::Latex::Parser`, which calls `Latexmath.parse(text, decimal: Plurimath.configuration.decimal)` and maps the returned `Latexmath::Model::Document` to a `Plurimath::Math::Formula` with `Plurimath::Latex::Mapper`. The preparation of the input is the one of the clause "Preparation of the input".

.Reading a formula (produced at the pinned `plurimath` commit)
[source,ruby]
----
Plurimath::Math.parse("\\frac{a}{b} + \\sqrt{x}", :latex).to_asciimath
----

[source]
----
frac(a)(b) + sqrt(x)
----

LaTeX takes the `locale:` parse option. It sets the decimal marker that `latexmath` is called with, so `1,5` is one number under a comma locale and two numbers with a comma between them otherwise:

[source,ruby]
----
Plurimath::Math.parse("1,5", :latex).value.map(&:class)
----

[source]
----
[Plurimath::Math::Number, Plurimath::Math::Symbols::Comma, Plurimath::Math::Number]
----

[source,ruby]
----
Plurimath::Math.parse("1,5", :latex, locale: :de).value.map(&:class)
----

[source]
----
[Plurimath::Math::Number]
----

`latexmath` is a runtime dependency. If it cannot be loaded, the parser raises `Plurimath::Math::MissingDependencyError` with the Gemfile line to add.

=== Writing

`Formula#to_latex` joins the output of each node with a space. It needs no LaTeX package beyond what the output commands themselves need. It takes the keyword options `formatter:` (default `nil`), `unitsml:` (default `{}`) and `options:` (default `nil`). `formatter:` and `unitsml:` work as for MathML (PM 1003). `options:` is a prepared options hash and takes the place of the other two.

[source,ruby]
----
Plurimath::Math.parse("frac(a)(b) + sqrt(x) + sum_(i=1)^n i", :asciimath).to_latex
----

[source]
----
\frac{a}{b} + \sqrt{x} + \sum_{i = 1}^{n} i
----

[source,ruby]
----
Plurimath::Math.parse(%q("speed" = d/t), :asciimath).to_latex
----

[source]
----
\text{speed} = \frac{d}{t}
----

[source,ruby]
----
Plurimath::Math.parse("alpha + oo", :asciimath).to_latex
----

[source]
----
\alpha + \infty
----

[source,ruby]
----
Plurimath::Math.parse("color(red)(x)", :asciimath).to_latex
----

[source]
----
{\color{red} x}
----

=== Constructs

Each row below is read as LaTeX, written as AsciiMath, and written back as LaTeX from the same formula. The "Written back" column is what `Formula#to_latex` gives, so a difference from the input shows what is normalised or lost:

* spaces are put around operators and between terms, and `\left` and `\right` are followed by a space;
* `\binom` becomes a matrix between braces, and `\operatorname` is dropped;
* `\sin x` is written as `\sin{x}`.

Two rows fail. The grammar has no `cases` environment, so `\begin{cases}` is refused. `\overbrace` with only a label above it is read, but the mapper builds no node for it, so writing the formula raises `Plurimath::Math::ParseError`; `\overbrace` reads when it has both a subscript and a superscript.
